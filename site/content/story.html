Port against an oracle

Each OCaml module in upstream's haxe/src became a Haxe module at the same path, its functions, branches and data in order. The reference compiler, built from the pinned commit, decides what is right: same arguments, same HXB, byte for byte.

OCaml leaks into the output

Most early mismatches were OCaml's: Hashtbl order (reproduced bucket by bucket), sorted PMap iteration, right-to-left argument evaluation, physical equality, 63-bit integers, float printing. All emulated in src/core/ds.

Macros

A port of the Eval interpreter and the macro API, then the 66 macro cases, --interp, the server, display and haxelib.

A back end of its own

On existing targets the port ran 1.3× to several times slower than OCaml. hxc, a back end writing C, built with clang, beat it: about 13% less CPU and 15% less memory. hxmc began as hxc's second back end, writing x86-64 instead of C, and grew into a target with SSA, ARM64, WebAssembly, its own linkers and a runtime in Haxe. It builds itself, so hxc was removed.

Every target, and upstream's tests

The JS, Lua, Python, PHP, Neko, HashLink, JVM, C++ and SWF generators came last; a fuzzer compares their output with the reference's. Upstream's target-independent CI job passes on the native build, and found bugs the conformance cases missed. The pin moves one upstream commit at a time, each rerun through the full matrix.
