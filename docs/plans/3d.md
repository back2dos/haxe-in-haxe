# 3D: `@hxmc/3d`, a scene layer for games

`@hxmc/gfx` is a portable GPU layer at about WebGPU's level (buffers,
textures, render targets, mips, pipelines, shaders written in Haxe) and
`@hxmc/os` gives windows, input, the app loop and audio. A 3D game needs
the layer above them: math that the CPU and the GPU agree on, a scene
graph, a camera, models loaded from glTF, lit materials, animation, input
mapped to actions, physics and tools. This plan is that layer:
`@hxmc/3d` (packages/3d), in seven steps, each useful on its own and each
proved by a demo on the site with golden images in CI.

What is built so far is at the end ([Status](#status)).

## Principles

- **Layered on gfx, gfx unchanged.** gfx stays the low layer, with its own
  roadmap ([graphics.md](graphics.md#left)). `@hxmc/3d` is ordinary gfx
  code: a program can use the scene graph with its own renderer, the
  renderer with its own scene, or drop to gfx for one pass (a custom
  post effect, a terrain) inside a frame the renderer draws. Nothing in 3d
  reaches into a back end. What 3d needs from gfx that gfx lacks
  (multisampling, depth-only passes, comparison samplers, cube textures)
  lands in gfx first, as gfx features with gfx's tests, and is listed in
  each step below.
- **One implementation of each thing.** One set of math types: gfx's
  shader types (`Vec2`, `Vec3`, `Vec4`, `Mat4`, `hxmc.gfx.shader`) are the
  CPU types too, so a matrix built on the CPU is the bytes the shader
  reads (std140, column by column) and a function written once runs on
  both. 3d adds only what shaders do not have (`Quat`, `Aabb`, inverses)
  as functions over those types, not a second vector library. One image
  decoder (today `@hxmc/ui`'s PNG and JPEG: moved down to a package both
  use when 3d needs textures, not copied). One loop (`hxmc.os.App`), one
  hot reload (`hxmc.dev.Hot`).
- **Small binaries.** Each feature is a set of classes a program reaches
  or not: a game without skinning links no skinning, one without glTF no
  JSON parser. No registry that keeps everything alive (no reflection,
  no string-keyed factories, no `Type.resolveClass`). The cost of each
  feature is measured (an executable per feature, natively and as
  wasm32-wasi) and kept in this document ([Sizes](#sizes)).
- **Fast builds.** No build macro over user classes for the scene; the
  only macros are gfx's `@:shader` (a few shaders, in the package) and
  the optional asset step. A change to a game's code types that code
  only (the module cache, `hxmc dev`).
- **Every target.** Browser (WebGPU, WebGL2), Linux, macOS, Windows,
  Android, iOS: whatever gfx runs on, with no per-target code in 3d. The
  renderer keeps to what WebGL2 and GLES 3.0 can do, and degrades (no
  MSAA, fewer shadow cascades) rather than splitting into two renderers.
- **Fast refresh of game state.** A game's world is data, carried across a
  reload by `hxmc.dev.Hot` ([docs/dev.md](../dev.md)) like `@hxmc/view`'s
  signals: the scene graph's transforms, the camera and the fixed-step
  clock save and load by key, GPU resources are released in
  `Hot.onDispose` and made again by the new build. A reload is a cold start
  with the same values: the player stays where they were.
- **Data first, no engine lock-in.** Nodes are plain classes with public
  fields; there is no component system to learn. Games that want an ECS
  build it on the same math and renderer.

## Package layout

npm `@hxmc/3d`, haxelib name `hxmc.3d`, Haxe package `hxmc.scene` (a
package name cannot start with a digit), depending on `hxmc.gfx` (and
`hxmc.os` through it).

| Module | Step | |
| --- | --- | --- |
| `hxmc.scene.math.*` | 1 | `Quat`, `Aabb`, `Transform` (TRS), `MathTools` (`inverse`, `transpose`, `lookAt`, ... on gfx's `Mat4` and `Vec3`) |
| `hxmc.scene.Node`, `Scene`, `Camera` | 1 | the transform hierarchy and what hangs on it |
| `hxmc.scene.FixedStep` | 1 | a fixed-timestep clock driven by `App.run`'s frames |
| `hxmc.scene.gltf.*` | 2 | glTF 2.0: `Gltf.parse` (.gltf JSON and .glb), the document as typed data, `GltfScene` (to nodes and meshes) |
| `hxmc.scene.render.*` | 3 | `Renderer`, `Mesh`, `Material`, `Light`, the shaders |
| `hxmc.scene.input.*` | 4 | `Actions`: named actions bound to keys, gamepad buttons and axes, touch |
| `hxmc.scene.anim.*` | 5 | `Clip`, `Skin`, `Animator` |
| `hxmc.scene.physics.*` | 6 | `World`, `Body`, shapes |
| `hxmc.scene.debug.*` | 7 | the overlay (`@hxmc/ui`), frame timing |

## The steps

### 1. Math, the scene graph, a camera and a loop

- **Math.** gfx's `Vec3`, `Vec4`, `Mat4` (immutable `@:hxmc.struct`
  values: copied, never allocated on hxmc's targets) with `ShaderMath`'s
  builtins (`dot`, `cross`, `normalize`, `mix`, ...). Added in 3d:
  `Quat` (a unit quaternion: from an axis and angle, from Euler angles,
  `*`, `slerp`, `rotate(v)`, `toMat4`), `Aabb` (min, max: `union`,
  `transform(m)`, `contains`, `intersects`, a ray test), and `MathTools`
  as a static extension of `Mat4` (`inverse`, `transpose`, `lookAt`,
  `compose(t, r, s)`, `transformPoint`, `transformDir`). Shader code can
  call the parts that are plain math (gfx's macro compiles any static
  function on its types), so a function such as `Quat.rotate` is written
  once.
- **Scene graph.** `Node`: a name, a local `position`, `rotation` and
  `scale`, a parent and children, and what it carries (a mesh, a light, a
  camera); its world matrix computed on demand and cached until a
  transform above it changes (a version number per node, no traversal
  per frame for still parts). `Scene` is the root plus the lists the
  renderer walks (meshes, lights) kept up to date on `add`/`remove`.
- **Camera.** `Camera`: perspective (vertical field of view, near, far)
  or orthographic, on a node; `view` (the node's world matrix inverted),
  `projection(aspect)` (gfx's clip space: y up, z 0 to 1), `viewProjection`,
  and `ray(x, y)` for picking.
- **Loop.** `FixedStep`: a fixed simulation rate (60 Hz by default) driven
  by `App.run`'s variable frames, with an accumulator (at most a few steps
  a frame, so a stall does not spiral), and the interpolation factor
  between the last two states for drawing. Game code reads it, it owns
  nothing else.
- **Hot.** `FixedStep` and a node's transform save and load by key
  (`Hot.keep`), a demo shows the camera and the scene's state surviving a
  rebuild.
- **Demo:** a scene of cubes in a hierarchy (a small solar system), drawn
  with a plain gfx shader; golden image native and in the browser.

### 2. glTF 2.0

- **Loading.** `Gltf.parse(bytes)`: the JSON form (.gltf, buffers as
  `data:` URIs or files a resolver returns) and the binary form (.glb:
  the JSON chunk and the BIN chunk). The document as typed data
  (`GltfDoc`: buffers, views, accessors, meshes and primitives,
  materials, textures, samplers, images, nodes, scenes, cameras), checked
  on read (indices in range, accessor sizes inside their views), no
  `Dynamic` past the JSON reader. Accessors of every component type,
  normalized integers, strides, sparse accessors later.
- **To the scene.** `GltfScene.build(doc, device)`: a `Node` per glTF node
  (TRS or a matrix), a `Mesh` per primitive (positions, normals, UVs,
  tangents, indices; vertex buffers interleaved for the renderer's
  layout, normals generated when missing), a `Material` per material
  (`pbrMetallicRoughness`: base colour, metallic, roughness and their
  textures, normal, occlusion and emissive textures, alpha mode and
  cutoff, double-sided).
- **Images.** PNG and JPEG through the decoders `@hxmc/ui` already has,
  moved to a package both depend on; in the browser optionally the
  browser's own decoder (`createImageBitmap`) through the os imports.
- **The asset step (optional).** A macro (`Asset.gltf("model.glb")`) or a
  command (`haxe --run hxmc.scene.gltf.Pack`) that reads a model at build
  time and writes a compact form: vertex data already interleaved in the
  renderer's layout, indices narrowed to 16 bits where they fit,
  quantized normals and UVs (`KHR_mesh_quantization`'s rules), unused
  attributes and nodes dropped, images re-encoded or kept. The runtime
  then has no JSON parser at all (a size win measured in [Sizes](#sizes)),
  and the asset step uses the same reader, so there is one glTF
  implementation.
- **Extensions** later, as games ask: `KHR_texture_transform`,
  `KHR_materials_emissive_strength`, `KHR_lights_punctual` (step 3's
  lights), `KHR_mesh_quantization`, `EXT_meshopt_compression`, Draco
  never (a decoder too large for its gain here).
- **Demo:** a small model checked in (generated by a script in the
  repository, MIT like the rest), loaded and drawn; its structure tested
  against the generator's on Eval and natively.

### 3. Lit PBR rendering

- Materials: glTF's metallic-roughness model (Cook-Torrance, GGX
  distribution, Smith visibility, Schlick Fresnel), base colour and
  emissive in linear light, sRGB textures decoded by the sampler
  (`RGBA8Srgb`), output tone mapped (ACES fitted, or Khronos PBR Neutral)
  and encoded to sRGB, alpha blend and mask.
- Lights: directional, point and spot (`KHR_lights_punctual`), a
  hemisphere ambient, then image-based lighting from an environment
  (prefiltered specular mips and irradiance, computed at load on the GPU),
  and the same environment as a skybox.
- Shadows: a shadow map for the directional light (cascades later), PCF.
  Needs from gfx: depth-only passes and comparison samplers (WebGL2 and
  GLES 3.0 have both).
- MSAA: needs gfx's multisampled targets and resolve
  ([graphics.md](graphics.md#left)); without it (or with it off), FXAA as
  a post pass.
- Instancing: meshes drawn many times in one call (gfx's `step: Instance`
  layouts), batched by mesh and material each frame.
- The renderer's frame: frustum culling with each mesh's `Aabb`, opaque
  front to back, then transparent back to front; one uniform block per
  draw through gfx's uniform ring (no allocation per frame), bind groups
  when gfx has them.
- **Demo:** the glTF scene lit, shadowed and tone mapped; the glTF
  sample models' material tests where licences allow.

### 4. Input actions

- `Actions`: named actions (`jump`, `move`) bound to keys, mouse buttons,
  gamepad buttons and axes and touch regions; each a button (pressed,
  held, released this step) or an axis (-1 to 1, 2D for sticks and
  virtual sticks), read once per fixed step so input and simulation agree.
- Gamepads need `@hxmc/os`: XInput (Windows), GameController.framework
  (macOS, iOS), evdev (Linux), Android's input events, the browser's
  Gamepad API; landed in os with os's tests.
- Bindings are data (rebinding at run time, saved by the game).
- **Demo:** a character moved by keyboard, gamepad or a virtual stick.

### 5. Animation

- Keyframe clips (glTF animations: translation, rotation, scale, weights;
  step, linear and cubic spline), sampled and blended (cross-fades,
  additive layers).
- Skinning: joints and inverse bind matrices from glTF, joint matrices in
  a uniform block or a texture (WebGL2's limits), four weights a vertex,
  in the vertex shader.
- Morph targets after skinning.
- **Demo:** a skinned glTF character walking.

### 6. Physics

- First a small built-in core, enough for most games: shapes (sphere,
  box, capsule, convex hull, a triangle mesh for static level geometry),
  a broad phase (a sweep and prune or a dynamic AABB tree), contacts (GJK
  and EPA, or SAT for boxes), a sequential impulse solver with sleeping,
  raycasts and overlaps, a character controller. Fixed step only.
- Later a binding to an established engine (Jolt or Rapier) for games
  that need more, behind the same `World` API, as a separate package so
  that its size stays out of programs that do not use it (Jolt through
  the C interop when it can bind C++, Rapier as a wasm module in the
  browser).
- **Demo:** boxes falling on a level mesh, shot with raycasts.

### 7. Tooling

- A debug overlay drawn with `@hxmc/ui` on top of the 3D frame: frame
  time (CPU and GPU), draw calls, triangles, a scene tree to inspect and
  edit transforms, toggles for wireframe, bounds and shadow cascades.
- Frame timing: GPU timestamps where back ends expose them.
- An editor later, built from the same pieces (the scene graph, the
  renderer, the overlay), saving scenes as glTF.

## Testing

Each step gets the lanes gfx has ([docs/testing.md](../testing.md),
"Graphics"):

- `make 3d-check`: the unit tests (math, the scene graph, the camera, the
  loop, the glTF reader) on Eval and natively, then the renderer's frames
  against golden images, headless on llvmpipe (packages/gfx's rule:
  `GfxTest.compareBytes`), in the gfx job of CI.
- `make 3d-web-check`: the same frames on WebGPU and WebGL2 in headless
  Chromium (packages/gfx's compare.mjs), also in the gfx job.
- Later the other back ends (Metal, D3D11 on WARP, Android, iOS) through
  gfx's existing jobs, once the scenes are part of their test programs.

## API sketches

Provisional: these follow the survey above once it lands; what is built
is in packages/3d/README.md.

```haxe
import hxmc.gfx.*;
import hxmc.gfx.shader.*;
import hxmc.os.*;
import hxmc.scene.*;
import hxmc.scene.math.*;
import hxmc.scene.gltf.*;
import hxmc.scene.render.*;
using hxmc.scene.math.MathTools;

class Game {
	static function main() {
		var window = new Window("Game", 1280, 720);
		var device = Device.create(window.surface);
		var renderer = new Renderer(device);

		// a model, read at run time (or at build time: Asset.gltf("level.glb"))
		var doc = Gltf.parse(sys.io.File.getBytes("level.glb"));
		var scene = new Scene();
		scene.add(GltfScene.build(doc, device));

		var sun = new Node("sun");
		sun.light = Light.directional(new Vec3(1, 0.95, 0.9), 3.0);
		sun.rotation = Quat.fromEuler(-0.9, 0.4, 0);
		scene.add(sun);

		var eye = new Node("camera");
		eye.camera = Camera.perspective(Math.PI / 3, 0.1, 200);
		eye.position = new Vec3(0, 2, 6);
		eye.lookAt(new Vec3(0, 0, 0));
		scene.add(eye);

		var player = scene.find("player");
		var step = new FixedStep(1 / 60), last = Sys.time();
		App.run(() -> {
			var now = Sys.time();
			step.advance(now - last, dt -> {
				// the simulation: fixed steps
				player.rotation = player.rotation * Quat.axisAngle(new Vec3(0, 1, 0), dt);
			});
			last = now;
			var enc = device.beginFrame();
			if (enc == null) return;
			renderer.draw(enc, scene, eye.camera);
			device.endFrame();
		}, e -> if (e.kind == Close) window.close());
	}
}
```

The main types:

```haxe
// math: immutable values, gfx's Vec3/Vec4/Mat4 plus these
abstract Quat(QuatData) {
	function new(x:Float, y:Float, z:Float, w:Float);
	static function identity():Quat;
	static function axisAngle(axis:Vec3, angle:Float):Quat;
	static function fromEuler(x:Float, y:Float, z:Float):Quat;
	@:op(A * B) static function mul(a:Quat, b:Quat):Quat;   // b first
	function rotate(v:Vec3):Vec3;
	function normalized():Quat;
	function conjugate():Quat;
	function toMat4():Mat4;
	static function slerp(a:Quat, b:Quat, t:Float):Quat;
}

class MathTools {   // using: on gfx's Mat4 and Vec3
	static function inverse(m:Mat4):Mat4;
	static function transpose(m:Mat4):Mat4;
	static function compose(t:Vec3, r:Quat, s:Vec3):Mat4;
	static function lookAt(eye:Vec3, target:Vec3, up:Vec3):Mat4;   // a view matrix
	static function transformPoint(m:Mat4, p:Vec3):Vec3;
	static function transformDir(m:Mat4, d:Vec3):Vec3;
}

@:structInit final class Aabb {
	final min:Vec3;
	final max:Vec3;
	function union(b:Aabb):Aabb;
	function transform(m:Mat4):Aabb;
	function contains(p:Vec3):Bool;
	function intersects(b:Aabb):Bool;
	function ray(origin:Vec3, dir:Vec3):Float;   // distance, or -1
}

// the scene graph
class Node {
	var name:String;
	var position:Vec3;      // setters mark the world matrices below stale
	var rotation:Quat;
	var scale:Vec3;
	var parent(default, null):Null<Node>;
	var children(default, null):Array<Node>;
	var mesh:Null<MeshRef>;  // what it carries: a mesh, a light, a camera
	var light:Null<Light>;
	var camera:Null<Camera>;
	function add(child:Node):Node;
	function remove(child:Node):Void;
	function local():Mat4;
	function world():Mat4;   // cached until a transform above changes
	function find(name:String):Null<Node>;
	function lookAt(target:Vec3, ?up:Vec3):Void;
}

class Scene extends Node {
	function walk(f:Node->Void):Void;
}

class Camera {
	static function perspective(fovY:Float, near:Float, far:Float):Camera;
	static function orthographic(height:Float, near:Float, far:Float):Camera;
	var node(default, null):Node;
	function view():Mat4;
	function projection(aspect:Float):Mat4;
	function viewProjection(aspect:Float):Mat4;
	function ray(x:Float, y:Float, aspect:Float):{origin:Vec3, dir:Vec3};   // x, y in -1..1
}

class FixedStep {
	function new(dt:Float, maxSteps:Int = 5);
	var time(default, null):Float;     // simulated seconds
	var alpha(default, null):Float;    // 0..1 between the last two steps, for drawing
	function advance(frame:Float, step:Float->Void):Int;   // the steps taken
}

// glTF
class Gltf {
	static function parse(bytes:Bytes, ?resolve:String->Bytes):GltfDoc;   // .gltf or .glb
}
class GltfDoc {   // typed, checked data
	var nodes:Array<GltfNode>;
	var meshes:Array<GltfMesh>;
	var materials:Array<GltfMaterial>;
	var scenes:Array<GltfSceneDef>;
	var scene:Int;
	function floats(accessor:Int):Array<Float>;   // any component type, normalized
	function indices(accessor:Int):Array<Int>;
}
class GltfScene {
	static function build(doc:GltfDoc, device:Device, ?scene:Int):Node;
}

// rendering
class Renderer {
	function new(device:Device, ?options:RendererOptions);   // msaa, shadows, toneMapping
	var exposure:Float;
	var ambient:Vec3;
	function draw(enc:Encoder, scene:Scene, camera:Camera):Void;   // records the frame's passes
}
class Mesh {   // gfx buffers, a bound and its primitives' materials
	var bounds(default, null):Aabb;
}
class Material {
	var baseColor:Vec4;
	var metallic:Float;
	var roughness:Float;
	var emissive:Vec3;
	var baseColorTexture:Null<Texture>;
	var alpha:AlphaMode;   // Opaque, Mask(cutoff), Blend
	var doubleSided:Bool;
}
class Light {
	static function directional(color:Vec3, intensity:Float):Light;
	static function point(color:Vec3, intensity:Float, range:Float):Light;
	var castShadows:Bool;
}

// input (step 4)
class Actions {
	function bind(action:String, binding:Binding):Void;   // Key(k), Pad(button), Axis(stick, x), Touch(region)
	function pressed(action:String):Bool;
	function held(action:String):Bool;
	function axis(action:String):Float;
	function stick(action:String):Vec2;
}
```
